# Product-change handoffs

A handoff lets another runner resume an authorised task without repeating work
or expanding its scope.

Create a dated Markdown file only when a durable handoff is actually needed.
Do not create routine handoff noise.

Every handoff must include:

1. work item and Airtable record ID;
2. approved OpenSpec change and exact revision;
3. authority granted and actions still explicitly unapproved;
4. files changed and ownership/overlap warnings;
5. last verified checkpoint and commands/evidence;
6. current branch and commit, if any;
7. preview/live URLs, if any, with their verification status;
8. blocker or the single next action;
9. lease state and expiry;
10. a statement that no participant data, secrets or tokens are included.

Corrections are appended with a timestamp. Do not rewrite the original account
of what a runner observed.
