# Retention-window amendment

**Decision date:** 26 September 2026  
**Decision:** Approved by Graham in direct conversation  
**Exact approval:** “do that - sounds good”

## Change

The current Phase 3.1 implementation package uses a **14-day** fixed retention
window for incomplete public responses, with **one reminder after seven days**.
Saving or resuming does not extend the original deadline.

This supersedes the seven-day deletion and day-three reminder timings in the
previously approved implementation proposal. That proposal remains unchanged as
historical evidence of what was approved at the earlier gate. The current
schema, participant copy, lifecycle, build and acceptance-test documents have
been amended to the new timing.

## Rationale

Fourteen days gives a busy participant two weekends in which to return while
remaining materially shorter than 30 days. It balances completion opportunity
with the principle that identifiable incomplete answers should not be held
longer than needed.

## Approval effect

This approves the revised timing within the implementation package. It does not
authorise an Airtable schema change, a real reminder, a deletion, public
activation, participant contact or production release.
